# OS996 — 智能家庭管家（STM32 固件）

基于 **STM32F407ZET6 + FreeRTOS** 的多传感器采集与云端联动子系统。

搭配 [ESP32 MQTT 桥接固件](https://github.com/) 组成完整的"端 → 云 → 端"链路。

---

## 系统架构

```
┌──────────────┐   UART    ┌──────────────┐   WiFi/MQTT   ┌──────────┐
│  STM32F407   │◄─────────►│  ESP32-S3    │◄─────────────►│  云平台   │
│              │  帧协议    │              │               │ (Broker) │
│ · 传感器采集  │  CRC16    │ · WiFi       │               └────┬─────┘
│ · JSON 组包  │           │ · MQTT 桥接   │                    │
│ · 场景联动    │           │ · 协议转换    │               ┌────▼─────┐
│ · 声光报警    │           │              │               │  MQTTX   │
└──────────────┘           └──────────────┘               └──────────┘
```

**职责划分**：STM32 负责硬实时采集、JSON 序列化与本地联动；ESP32 只做传输层协议转换（不解析 JSON），职责单一便于调试。

## 功能

| 模块 | 说明 |
|---|---|
| **温湿度** | GXHT30，I2C1，**CRC-8 数据校验** |
| **人体红外** | HC-SR501，GPIO 输入，**3 次采样消抖 + 60 秒预热状态机** |
| **可燃气体** | MQ-2，ADC + DMA 循环采集，**指数移动平均(EMA)滤波** |
| **场景联动** | 气体超标 **且** 人体在位 → 声光报警（双条件避免误报） |
| **云端控制** | 接收 MQTT 指令控制 LED / 蜂鸣器（限时脉冲，自动回落） |
| **协议** | 自定义串口帧：`0xAA 0x55 + CMD + LEN + PAYLOAD + CRC16` |

## 硬件

| 器件 | 型号 | 接口 |
|---|---|---|
| MCU | STM32F407ZET6（正点原子探索者 V3） | — |
| 温湿度 | GXHT30 | I2C1：PB8(SCL) / PB9(SDA) |
| 人体红外 | HC-SR501 | PE5（下拉输入） |
| 可燃气体 | MQ-2 | ADC1_IN4 = PA4 |
| 调试串口 | 板载 CH340 | USART1：PA9/PA10 |
| ESP32 串口 | — | USART2：PA2(TX) / PA3(RX) |
| 指示 | LED0=PF9 / LED1=PF10 / BEEP=PF8 | 低电平有效（蜂鸣器为高电平有效） |

### ⚠️ 两个硬件注意点

**1. MQ-2 的模拟输出必须分压**

MQ-2 的 AO 是 **0~5V**，而 STM32 的 **ADC 引脚只能承受 3.3V**（TTa 类型；注意多数数字 GPIO 是 5V 容忍的 FT 类型，但 ADC 引脚不是）。

本设计用 **500Ω / 500Ω 分压**，比值 0.5，5V → 2.5V，留 0.8V 余量。软件里再除回还原真实电压。

**2. HC-SR501 需要 5V 供电**

手册规定工作电压 **4.5~20V**，接 3.3V 不工作。但它的 **OUT 输出是 3.3V**（内部有稳压器），所以直接接 GPIO 是安全的。

## 软件架构

```
Core/
├── Src/
│   ├── main.c              CubeMX 生成 + USER CODE 区（任务实现、帧回调）
│   ├── bsp_gxht30.c        温湿度传感器驱动（I2C + CRC-8）
│   ├── bsp_pir.c           人体红外驱动（GPIO + 消抖状态机）
│   ├── bsp_mq2.c           气体传感器驱动（ADC + DMA + EMA 滤波）
│   ├── bsp_alarm.c         执行器驱动（LED / 蜂鸣器极性封装）
│   ├── bsp_protocol.c      帧协议：CRC16 + 组帧发送 + DMA 接收状态机
│   └── log.c               线程安全日志（互斥量 + 定长缓冲）
├── Inc/                    对应头文件
└── cJSON/                  cJSON 1.7.19（MIT License）
```

### FreeRTOS 任务划分

| 任务 | 优先级 | 栈 | 职责 |
|---|---|---|---|
| `CommTask` | AboveNormal1(32) | 2 KB | 串口帧收发（轮询 DMA 环形缓冲） |
| `SensorTask` | Normal1(25) | 3 KB | 三传感器采集 + JSON 组包发送 |
| `AlarmTask` | Normal1(25) | 3 KB | 场景联动判断 + **独占**所有执行器输出 |
| `defaultTask` | Normal(24) | 1 KB | 空闲 |
| `DisplayTask` | Low(8) | 1.5 KB | 预留（OLED） |

**划分依据**：按**时间特性**和**资源耦合度**，不按器件数量。三个传感器都是秒级慢信号且共用 I2C 总线，合并到一个任务天然避免总线竞争。

**执行器独占**：全工程只有 `AlarmTask` 写 LED / 蜂鸣器，杜绝多任务抢同一 GPIO 的资源竞争。

## 串口帧协议

```
偏移   长度    字段        说明
────   ────    ──────      ────────────────────────────────
 0      1      HEAD1       0xAA
 1      1      HEAD2       0x55
 2      1      CMD         0x01=传感器上报 0x02=控制下发
 3      1      LEN         载荷长度（≤200）
 4     LEN     PAYLOAD     JSON 文本
4+LEN   2      CRC16       校验值，小端（低字节先）

总长度 = LEN + 6
```

**CRC 计算范围**：`CMD + LEN + PAYLOAD`（不含帧头）
**算法**：CRC16-MODBUS，多项式 `0xA001`，初值 `0xFFFF`，逐位计算。
> 已用国际标准测试向量验证：输入 `"123456789"` 输出 `0x4B37`。

### 接收实现

**DMA 循环接收 + 任务内轮询解析**（不使用 IDLE 中断）：

- CubeMX 把 `DMA1_Stream5` 配成 Circular，配一次永久运行
- 任务读取 DMA 的 `NDTR` 寄存器算出新到字节数，喂给 7 态解析状态机
- **优点**：解析全在单一上下文，没有 ISR 与任务的同步问题
- **CRC 增量计算**：边收边算，无需先缓存整帧

## 踩过的坑（工程记录）

| 问题 | 现象 | 根因与修复 |
|---|---|---|
| **栈溢出静默卡死** | 串口输出里 `"SensorTask"` 变成 `"SensmTask"`，日志截断 | `AlarmTask` 只有 1 KB 栈却跑了 2 个 `printf`（单次 300~600 字节）。修复：栈加大到 3 KB，**并实现原本为空的栈溢出钩子**（原来溢出完全静默） |
| **ADC 假平均** | 滤波完全没效果 | "循环读 8 次取平均"——DMA 更新周期 9.4 µs 远慢于循环耗时（纳秒级），8 次读到的是同一个值。改为 **EMA 滤波**（α=0.1） |
| **多任务 printf 交织** | 两条日志内容互相插入 | `printf` 使用全局 `FILE` 结构非线程安全；且 115200 下发 90 字符需 7.8 ms，期间可被抢占。修复：**互斥量 + `vsnprintf` 到本地缓冲 + 单次整帧发送** |
| **日志被截断** | 换行丢失、两行黏连 | `LOG_LINE_MAX=160` 但 `[RX] payload` 需 162 字符。改为 256 |
| **ATK-DAP 识别不了** | `unable to find a matching CMSIS-DAP device` | 该探针只暴露 HID 接口。修复：OpenOCD 配置加 `cmsis-dap backend hid` |

## 已知限制

- **MQ-2 未做标定**，输出是相对值而非 ppm 浓度（需要标准气体标定 + 湿度补偿）
- **MQ-2 需 48 小时预热**才能稳定，新模块读数会持续漂移
- **报警阈值为固定值**，随传感器老化需重新调整（计划改为相对本底的自适应阈值）
- 调试用公共 MQTT Broker（明文 1883），生产环境应换 TLS + 鉴权
